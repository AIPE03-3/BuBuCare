## 一句話結論

現行邏輯在 **9 支正常動作影片上全部誤報（9/9）**；`geo-first` 把走路誤報清零、
整體幀誤報率從 44.7% 降到 11.9%，但**撿東西（4/5）與坐下（2/2）仍會誤報** ——
那些走的是遮擋判斷，`geo-first` 動不到。

---

## 為什麼改用單一動作短片

前一輪用 test4.mp4（6.2 分鐘、20 段跌倒的剪接長片），有三個問題：

| 長片的問題 | 短片如何解決 |
|---|---|
| 需要人工標註時間段 | **檔名即標籤**：`Fall*` 全片該觸發、其餘全片不該 |
| 剪接點污染 AcT 視窗 | 一鏡到底，沒有剪接 |
| 誤報率是各情境的**混合平均**，看不出系統在哪種動作上出錯 | 每支一個動作，直接指出「撿東西誤報幾次」 |

第三點最關鍵。長片算出「誤報率 56.5%」無法行動；短片算出「撿東西 4/5 誤報」
直接告訴你下一個該修哪裡。

## 測試素材

13 支單一動作短片，20 fps、8~12 秒、各約 300KB~1MB：

| 類別 | 支數 | 檔案 | 該觸發？ |
|---|---|---|---|
| `Fall*` | 4 | FallBackwardsS10, FallForwardS2, FallLeftS5, FallRightS5 | ✓ |
| `Pickupobject*` | 5 | S1, S3, S5, S6, S9 | ✗ |
| `SitDown*` | 2 | S2, S8 | ✗ |
| `Walk*` | 2 | S4, S10 | ✗ |

`Pickupobject`（撿東西）是刻意收的：**彎腰 = 變矮 + 位置偏下**，正好撞上遮擋判斷。

---

## 指標設計：事件級與幀級要分開

```
跌倒片抓到  4/4    ← 有幾支跌倒影片被抓到（事件級）
正常片誤報  9/9    ← 有幾支正常影片被誤報過（事件級）⭐
正常片幀誤報率     ← 所有正常影片的觸發幀比例（幀級）
```

**事件級才是護理師的體感** —— 她收到的是一則通知，不是一幀。幀誤報率 5% 聽起來很低，
但如果那 5% 分散在 9 支影片的 8 支裡，實際上就是被吵 8 次。

## 四個發現

### 1. 現行邏輯在正常動作上 100% 誤報（9/9）

走路、坐下、撿東西 —— 沒有一支逃得掉。這比長片算出的「誤報率 56.5%」更直觀：
實際部署等於**護理師每做一件事就被吵一次**。

### 2. 走路誤報全是純 AcT 造成的，`geo-first` 直接清零

```
WalkS10   43.8% → 0.0%
WalkS4    54.2% → 0.0%
```

且跌倒片幀召回幾乎沒損失（67.1% → 63.0%）。這比長片上看到的「誤報降 4.7 倍、
多漏 1 段」乾淨得多 —— 長片之所以像取捨，是因為把 20 種情境混在一起平均掉了。

### 3. 撿東西與坐下走的是遮擋判斷，`geo-first` 動不到

`pickupobject 4/5`、`sitdown 2/2` 在 `geo-first` 下依然誤報，與前一份報告
「OCCLUDED 佔 geo-first 殘餘誤報 87%」完全一致。**這是下一個要處理的目標。**

### 4. `geo-strict` 的「4/4 抓到」是假象

看幀召回只剩 **9.2%**：

```
FallBackwardsS10   0.7%   ← 全片只有 0.7% 的幀在報
FallLeftS5         2.4%
FallForwardS2      3.8%
```

整個跌倒過程只有零星一兩幀報得出來。真實場景這種「閃一下就消失」的訊號，
可能連 Kafka 都還沒送出去人就已經躺在地上五分鐘了。**確定不能用。**

> 這是 `geo-strict` 第二次被實測否決（前一次見上一份報告）。事件級指標
> （「抓到 4/4」）若不搭配幀級看，會再一次得出相反結論——與段級召回率的陷阱同源。

## 待確認：往前跌可能最難判

```
FallForwardS2   current 22.6% → geo-first 3.8%
```

其他三個方向在 `geo-first` 下都維持 55~80% 幀召回，只有**往前跌**掉到 3.8%。

推測原因：從俯視角看，人往前倒時軀幹在畫面上的**角度變化最小**，躺平判斷
（角度 < 40°）抓不到。

⚠️ **只有一支影片，不能下定論。** 需要再拍 3~5 支 `FallForward*` 確認。
若成立，這是幾何判斷的第二個盲區（第一個是趴跪 + 遮擋，見上一份報告 #19/#20）。

## 下一步：遮擋判斷需要「時間維度」

現在的遮擋判斷只看**當下這一幀**：

```python
if (h_box / normal_h_reference) < 0.70 and y2 > (img_h * 0.5):
    is_occluded = True     # 人「變矮」且位置偏下 → 立即觸發
```

它分不出三種「變矮」：

| 動作 | 變矮的特徵 |
|---|---|
| 撿東西 | 快速變矮，**1~2 秒後恢復** |
| 坐下 | 變矮後**穩定維持**在椅子高度 |
| 跌倒 | 快速變矮，**持續不恢復**，且掉到更低 |

加上「持續多久」就能區分。這與 hazard 偵測用的狀態機同源（連續 N 幀確認才成立）。

**代價是延遲**：要等 1~2 秒才確認。但現況是「無條件立即觸發」換來每次彎腰都誤報，
這個交易值得用數據算一次。`geo-strict` 已證明「要求 AcT 附議」不是解法，
時間維度是另一條路。

## 附帶收穫：這批短片是 AcT 重訓的現成資料

AcT 需要「連續 30 幀特徵序列 + 二分類標籤」。單一動作短片天然符合：
**`Fall*` = label 0、其餘 = label 1，檔名就是標籤**，不必額外標註。

目前 13 支太少（每類需 20~50 支），但格式完全正確，之後走重訓直接擴充即可。
注意現有主動學習資料集（單張快照 + 關鍵點）餵不了 AcT，理由見上一份報告。

## 已知限制

| 限制 | 說明 |
|---|---|
| 樣本數少 | 每類 2~5 支，單支影片的表現會明顯影響整體數字 |
| 缺 `Squat` / `LieDown` | 蹲下與正常躺臥沒有素材；用 `Pickupobject` 部分替代 |
| `FallForward` 只有 1 支 | 「往前跌最難判」的推測無法確認 |
| 單一場景 | 所有影片同一個房間、同一組人 |
| 不含 detr 那幾條防線 | 離床、座椅滑落、環境巡檢需要 rt_detr，本地跑不動 |
