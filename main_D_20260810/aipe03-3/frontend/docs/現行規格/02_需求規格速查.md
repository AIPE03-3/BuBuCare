## 功能需求 FR（重點）

| 編號 | 需求 |
|------|------|
| FR-1.1~1.4 | 接 RTSP 串流、姿態估測、多目標追蹤、規則高召回篩「疑似跌倒」 |
| FR-1.5 | 冷卻機制：同 Track ID 5 分鐘內不重複建事件；Track ID 漂移時以倒地位置空間鄰近度做第二層保護 |
| FR-2.1~2.4 | 疑似時送 VLM 複判，輸出結構化（是否跌倒／信心／嚴重度／描述／建議／通報草稿）；曖昧情境正確抑制 |
| FR-3.1~3.3 | 依區域查值班表定向通知；追蹤是否接手；逾時未接手自動升級並通知管理者 |
| FR-3.4~3.5 | 自動草擬交班／事故紀錄供人工審核；送醫、通報家屬須人工確認 |
| FR-4.1~4.3 | 接收邊緣事件建紀錄；維護事件生命週期；保存事件片段並產生連結 |
| FR-5.1~5.5 | 中控台即時顯示事件；Web Push 推播；一鍵接手／結案／誤報；顯示環境評分與趨勢；異常下降時標示「需注意」並推播 |
| FR-6.1~6.6 | 預設每 15 分擷圖送 VLM 環境評分（五向度、總分 100）；存分數並算與前次差；下降超閾值（預設 15）觸發提醒；保存歷史 |
| FR-7.1~7.3 | 標記誤報存入 Hard Negative Pool（記類型、標記者、時間）；提供清單與匯出 |
| FR-8.1~8.7 | 記 YOLO 信心分數並每日統計；誤報數趨勢與 VLM 推翻率；MLflow 版本管理；MLOps 面板與手動 fine-tune 入口；通過固定測試集門檻才人工升格；支援回滾；預留自動觸發接口 |
| FR-9.1~9.2 | （後續工作）跌倒風險分數趨勢化；事件庫 RAG 查詢 |

## 非功能需求 NFR（重點）

- 效能：偵測延遲 < 3–5 秒、通報延遲 < 5 秒；環境評分為週期任務，不得阻塞即時推論。
- 隱私安全：本地推論、影像不出場、事件片段短期保存屆期刪除、密碼雜湊、角色控管（admin／staff）。
- 可維護：模組化、Docker Compose；閾值可調（冷卻時間／評分週期／異常閾值）。
- 可移植：sensor-agnostic、edge-ready、支援 RTSP／WebCam。

## VLM 環境評分向度（§5.2 任務 B）

**四向度（已定案 2026-07-12）**：地面地板 30／通道暢通性 30／潛在危險物品 20／照明條件 20（總分 100，不含安全設施完整性）。原文件 4 vs 5 向度矛盾已由組長拍板採四向度版本。

**等級對照**：90–100% 良好／70–89% 注意／40–69% 警示／0–39% 危險。

| `/api/v1/env-scores/latest` | GET | 各攝影機最新評分 |
| `/api/v1/hard-negatives` | GET | HNP 清單 |

## 資料庫主要表（§5.6）

**events**：`event_id`(PK)、`device_id`(FK)、`event_type`、`status`(ENUM)、`confidence`、`severity`、`vlm_summary`、`video_url`、`track_id`、`bbox_center_x/y`、`detected_at`、`handler_user_id`。
規格 status 為 8 態（SUSPECTED/CONFIRMED/SUPPRESSED/COOLDOWN_SUPPRESSED/NOTIFIED/ACKNOWLEDGED/ESCALATED/RESOLVED）；⚠ 後端實作為三態＋verdict，見落差記錄。

**env_safety_scores**：`score_id`(PK)、`device_id`、`total_score`、五個分項 `floor/pathway/hazard/lighting/facility_score`、`overall_description`、`risk_factors`(JSONB)、`score_drop`、`alert_triggered`、`snapshot_url`、`assessed_at`。

**model_versions**：`version_id`、`model_type`、`version_tag`、`mlflow_run_id`、`status`(staging/production/retired)、`recall`、`false_positive_rate`、`map_50`、`training_samples`、`hard_negative_count`、`deployed_at`、`created_at`。

**model_daily_metrics**：`id`、`device_id`(nullable，NULL=全域)、`date`、`yolo_trigger_count`、`false_positive_count`、`avg_confidence`、`vlm_override_rate`、`hard_negative_pool_size`。

**hard_negative_pool**：`id`、`event_id`、`clip_url`、`label`（坐地/伸展/彎腰/攙扶/其他）、`note`、`labeled_by`、`created_at`。

**其他**：`devices`（id/device_uuid/location/status/stream_url）、`users`（user_id/username/password hash/role/email）、`notifications`（notify_id/event_id/channel/message_type/status/sent_at）、`residents`（非生物識別）、`risk_scores`（後續工作）。

## 冷卻機制與狀態機（規格版，§5.3~5.4）

冷卻雙層：①Track ID 5 分鐘冷卻 → 命中則 COOLDOWN_SUPPRESSED；②空間鄰近度（bbox 中心距離）保護 Track ID 漂移。
狀態機（規格）：疑似 SUSPECTED →（VLM）CONFIRMED → NOTIFIED → ACKNOWLEDGED →（逾時）ESCALATED → RESOLVED；VLM 判非跌倒 → SUPPRESSED 存入 HNP。⚠ 後端實作簡化，見落差記錄。

## 環境評分等級與閾值

評分週期預設 15 分（一天約 96 筆）；異常閾值預設 score_drop ≥ 15 觸發提醒；信心路由區間 0.85（高）／0.5（低）。⚠ 後端環境評分實作週期為 15 秒且目前無分數，見落差記錄。
