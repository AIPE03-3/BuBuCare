# Schema 設計檢查表

## 為什麼有這個 skill

過去設計資料表初稿時，常漏掉使用者先前在對話裡口頭提過的需求
（例如：company_id 多租戶欄位、把 location 拆成獨立表、staff 的主鍵、某欄位要不要 FK），
每次都要使用者逐條抓出來補。這個 skill 強制先對齊需求再動手。

## 動手寫任何 schema 之前，先做這件事

**產出一張「需求 ↔ 欄位」對照表，貼給使用者逐條確認，等他點頭才寫程式。**

表格三欄：

| 使用者提過的需求 | 對應的表 / 欄位設計 | 待確認的問題 |
| ---------------- | ------------------- | ------------ |
| （把對話裡講過的每一點列出來） | （每點對應到哪張表、哪個欄位、型別） | （我不確定的地方，例如要不要 FK、可不可為 null） |

## 每一欄位都要主動問清楚的四件事

1. **可不可以為 null**（nullable）——不要預設，逐欄問
2. **要不要 FK 連到別的表**——特別是 id / xxx_id 結尾的欄位
3. **固定選項的欄位**（status / 狀態 / 類型）——用 Enum 還是字串？（本專案慣例見 [[enum-columns-decision]]）
4. **要不要獨立成一張表**——重複出現的名稱（如 location）通常該拆表用 FK 連，不要塞字串

## 收尾

對照表確認完、開始寫 models.py 時，才進入正常的實作流程
（本專案用 SQLAlchemy 2.0 的 Mapped / mapped_column 寫法，跟現有 models.py 一致）。
